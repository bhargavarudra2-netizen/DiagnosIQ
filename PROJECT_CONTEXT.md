# Project Context — Life-Log App

> Paste this file into any AI coding session (Claude Code, etc.) before asking it to build a
> specific piece. It gives full context without needing the original planning doc.

## 1. What this app is

An AI-powered personal life log. The core analogy: **GitHub for your life.**

Developers don't summarize months of work — they just commit. Years later, GitHub
reconstructs the whole history. This app does the same for a person's day-to-day life.

## 2. The problem it solves

Most productivity/journaling apps fail because they ask the user to do the organizing:
create tasks, set priorities, categorize, estimate time, review the day, plan tomorrow.
That overhead is why people stop using them — **logging becomes work itself.**

## 3. The core philosophy (do not violate this)

> **The user records moments. The system remembers, organizes, understands, and plans.**

Concretely:
- The user only ever types short, natural, in-the-moment notes ("Finished English.",
  "Starting DSA.", "Tea break.").
- The user never manually tags, categorizes, estimates time, or writes summaries.
- All structure (activity, category, project, tags, confidence) is inferred by AI **after**
  the fact, asynchronously, from the raw text.
- The raw text is sacred and permanent — AI output is always additional metadata layered on
  top, never a replacement. If AI gets something wrong, the original entry is still intact
  and correct.

Any feature proposal that asks the user to manually categorize, tag, prioritize, or
structure their input at write-time is off-philosophy and should be reconsidered.

## 4. Primary user flow

1. Open app → single text box: **"What's happening right now?"**
2. Type a short note, tap **Commit**.
3. Entry is timestamped and saved instantly (raw text first, no AI blocking this step).
4. In the background, AI structures the entry (activity, category, project, tags).
5. Entries appear in a chronological **Timeline** (WhatsApp/GitHub-activity style).
6. On request (or nightly), AI generates a **Daily Summary** and a **Plan for tomorrow**.
7. User can ask natural-language questions across their whole history ("When did I start
   learning React?").

## 5. Feature inventory

**Authentication**: Email login, Google login, per-user cloud sync. (Future: Face ID,
fingerprint, 2FA.)

**Live Activity Feed / Home**: one input box, one Commit button, nothing else.

**Automatic timestamping**: date, time, timezone, user ID — all implicit, never typed.

**Original text storage**: raw text stored permanently and independently of AI output.

**AI structured storage**: per entry — activity finished, activity started, category,
confidence score.

**Timeline**: chronological feed of all entries, newest at bottom, grouped by day.

**AI Summary**: on-demand or nightly — Completed / Pending / Ideas / Time Spent / Suggested
Tomorrow.

**AI Search**: natural-language search across the full history of logs.

**Projects**: user-created (e.g. "Infinity", "DSA", "Fitness"); AI links entries to projects
automatically or suggests a link for confirmation — never forces a manual choice up front.

**Tags**: always AI-generated, never manually typed (Study, Coding, Reading, Break,
Exercise, Idea, etc.).

**Analytics**: daily/weekly/monthly/yearly views — coding hours, reading hours, sleep,
productivity, streaks, most active time.

**AI Planner**: tomorrow's plan is generated by AI from recent activity and unfinished
items, not written manually.

**Cloud Sync**: instant, cross-device, login-and-everything-returns.

**Export**: JSON, PDF, Markdown, CSV — the app must never lock in user data.

**Guardian Mode (future)**: an owner can grant scoped read access to a parent/teacher/
mentor/coach.

## 6. What the AI is and isn't

The AI is **an organizer, not a chatbot.** Its job:
- Structure raw logs into activity/category/project/tags.
- Detect projects, activities, habits.
- Build daily/weekly/monthly summaries.
- Generate tomorrow's plan.
- Search across historical entries.
- Notice unfinished work and productivity drops.

Later: a conversational layer on top of this ("What did I do last Friday?", "How many
hours have I spent on Infinity?") — but this is a UI on top of the same structured data,
not a separate general-purpose chatbot.

## 7. UI/design principles

- Minimal. No clutter, no glassmorphism, no decorative animation.
- **Speed over effects** — this is a rule, not a preference.
- Home: large input box + Commit button + today's timeline below it.
- Bottom navigation: Home, Timeline, AI, Analytics, Profile.
- Timeline styled like GitHub's activity graph crossed with WhatsApp's message list —
  simple cards with timestamp, message, AI tags.
- AI screen: chat-style interface.
- Analytics: heatmaps, graphs, project progress, streaks — clean, no clutter.
- Dark theme by default, with a selectable accent color.

## 8. Architecture

| Layer | Choice |
|---|---|
| Frontend | React Native (Expo), TypeScript |
| Backend | FastAPI (Python) |
| Database / Auth / Storage / Realtime | Supabase (PostgreSQL) |
| AI | Gemini or OpenAI API (future: local models) |
| File/media storage | Supabase Storage (images, voice, files) |

Supabase was chosen specifically because one service covers auth, database, storage, and
realtime sync — minimizing infra for an MVP.

## 9. Data model (conceptual)

- **Users**: id, name, email, photo.
- **Entries**: id, user_id, timestamp, raw_text, ai_summary, activity, project, tags,
  metadata. *(raw_text and ai_summary are always separate fields — never merge them.)*
- **Projects**: id, name, color.
- **Analytics**: generated on the fly / cached, not treated as a primary source of truth.

## 10. Roadmap (build order)

1. **Phase 1** — Login, database, Add Entry, Timeline, Cloud Sync. This alone should be a
   usable, dogfoodable app.
2. **Phase 2** — AI layer: raw text → structured data, storing both.
3. **Phase 3** — Daily Summary, Tomorrow's Plan, Search.
4. **Phase 4** — Projects, Tags, Analytics.
5. **Phase 5** — Guardian Mode, Notifications, Widgets, Voice, Images, Files.

## 11. Working principle for AI-assisted development

Do not ask an AI coding tool to build the whole app in one shot. Give it **one modular
task at a time** (a single screen, a single endpoint, a single schema change), matching
the phase it belongs to above. Always give it this context document plus the current
schema/RLS policies before asking for backend work, so it doesn't guess at table shapes.

## 12. One-line summary to repeat when scope-checking any new feature

> **The user records moments. The system remembers, organizes, understands, and plans.**
> If a proposed feature makes the user do more organizing at write-time, it's wrong for
> this app.
